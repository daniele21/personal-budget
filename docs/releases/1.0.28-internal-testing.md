## Scope — read-only diagnostic, NOT a listener-binding fix

[Affected-device incident #68](https://github.com/daniele21/personal-budget/issues/68) remained reproducible on Aura 1.0.27 after a successful post-update period: Android showed active selected-source notification(s), while Aura's active process interval reported `BIND_WAITING`, 12 recovery passes, two requests submitted, ten deferred and zero V2 observed service starts or connections. These counters do not tell us *why* Android did not bind the listener.

[PR #84](https://github.com/daniele21/personal-budget/pull/84) adds strictly bounded process lifecycle diagnostics to **Payments to review → Local detector diagnostics**:

- **Current Aura process age:** a coarse age bucket from Android's monotonic process-start time, not listener age.
- **Previous Aura process exit:** an allowlisted Android OS reason category from `ActivityManager.getHistoricalProcessExitReasons` for Aura's **own default app process only**.
- **Time since previous exit:** a coarse bucket, not an exact timestamp.
- `NO_RECORD` means OS has no matching history, **not** proof the process never died. `UNAVAILABLE` covers absent query/time evidence.
- Historical exit reason can belong to an earlier package update or another app session; neither a recent exit nor a long-lived process proves the listener's binder state.

No OS exit descriptions, exception messages, trace streams, tombstones, account/device identifiers, PID, UID, precise event timestamps, bank notifications, payment contents, persistent telemetry or network upload are used. The existing owner/opt-in/supported-source/privacy gate, local candidate store, parser, ledger, Android permissions, retry/backoff, and NotificationListenerService lifecycle remain unchanged.
