# Review Reference Quality

Inspect code, tests, CI, `.engineering/*`, current docs and `design/*`; never grade from README claims alone.

Assess architecture/ownership, dependency complexity, resource/concurrency/failure lifecycle, privacy/security/data migration, observability, layered testing, critical-journey E2E, performance, reproducible build/package behavior, artifact identity/retention/delta, zero-residue runtime, repository/CI hygiene, documentation lifecycle and agent operability. For product UI also assess task model, hierarchy/disclosure/defaults, critical states/recovery, accessibility/adaptive behavior, design ownership, purposeful motion/graphics and evidence quality.

Distinguish unit/integration/E2E/smoke and host/browser/emulator/physical evidence. Mark unavailable evidence pending, not passing. Recommend the smallest high-leverage fixes and report current maturity, blockers to the next level, important debt and a prioritized dependency-aware remediation plan.
