# Design Product Experience

For structural UX use the full order; for interaction/visual-only work start at the smallest affected layer:

`user outcome -> task model -> IA/critical journey -> information/action hierarchy -> disclosure/defaults -> states/feedback/recovery -> adaptive/platform -> accessibility -> design system -> motion -> visual polish/graphics -> validation`

Rules:
- Model what the user thinks they are doing, not internal services or storage.
- Make primary, secondary and destructive actions visually/semantically distinct.
- Keep advanced/diagnostic complexity progressively disclosed and normal workflows strong by default.
- Cover loading, empty, error, disabled, permission/offline and recovery states when reachable.
- Preserve Android touch/navigation conventions, responsive layouts, focus/semantics/text scaling/contrast and reduced motion.
- Reuse canonical components and Aura brand tokens before adding patterns.
- Motion must serve feedback, continuity, progress, spatial meaning or attention; frequent financial controls stay restrained.
- Graphics/data visualization must support a user decision and functional UI must remain understandable without decoration.
- Define component, accessibility, E2E, adaptive and usability evidence proportional to the claim.
